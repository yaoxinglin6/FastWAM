# 恢复系数实验后续调整

## 2026-09-09：反弹阈值

按用户指定，将正式任务和独立验证脚本的反弹阈值统一设为 0.5 m/s。修改保存在本地工作副本，当前不提交实验。

验收：确认 SAPIEN 3.0.0b1 支持 `SceneConfig.bounce_threshold`，赋值发生在创建场景之前，并完成两个 Python 文件的语法检查。正式运行时仍需读回场景配置并检查接触稳定性。

场景参数转发已修复。后续正式扫描仍需先验证真实碰撞材质读回及接触稳定性；独立验证脚本的接触判定/回弹高度算法尚未修复，不能用其当前 bounce_height 作为机制证据。此前扫描结果保留为历史记录。

## 单因素控制与覆盖范围

正式任务只向 `setup_scene` 转发 `restitution`，不因本次修复同时启用其他场景参数覆盖。反弹阈值为 0.5 m/s，时间步维持 1/250 s。

| 原始材质路径 | 未扫描时 | 扫描时 |
| --- | --- | --- |
| 任务显式 scene 材质：box、sphere、cylinder、桌面等 | 静/动摩擦 0.5/0.5，恢复系数 0 | 摩擦保持 0.5/0.5，仅恢复系数改为扫描值 |
| builder 默认材质：OBJ/GLB/actor 网格及桌腿 | 使用实际引擎默认材质 | 读取并保留默认材质的静/动摩擦，只替换恢复系数 |
| 未覆盖的地面、机器人/夹爪、URDF 等 | 保持各自原设置 | 保持各自原设置 |

SAPIEN 3.0.0b1 的引擎默认材质初始值是 0.3/0.3/0.1（静摩擦/动摩擦/恢复系数）。实现从 `sapien.physx.get_default_material()` 读取摩擦，不硬编码 0.3，也不修改这个共享材质。覆盖集合在各个扫描值下保持一致；外观材质、形状、质量、惯量、接触偏移和关节驱动不随该扫描改变。这里扫描的是指定表面的材质恢复系数，碰撞对的有效响应仍取决于双方材质及求解器。

不传 `restitution` 的原始材质基线与 `restitution=0` 的扫描参考不同：前者保留网格的原始恢复系数（默认 0.1），后者将覆盖的网格恢复系数也设成 0。因此应分别记录无覆盖基线与 e=0 参考；两者都使用本次固定的 0.5 m/s 阈值，并在所有 e 组中使用相同种子、策略和其他设置。

扫描入口和场景入口要求恢复系数为 [0,1] 内的有限数，不再接受历史扫描中的 1.2。旧实验表格保留原始记录，不作为新代码生效或单因素控制的证据。
